# 未核验原文阅读与下载 · 2026-10-05

保存报告未通过完整性校验时，助手卡和报告页继续停用正常答案、图表、数学结果、派生行动及常规 Markdown/JSON 报告导出。现在两处共用只读原文阅读器，解决长单行文本必须横移约十六万像素才能找到字段的问题。

## 普通读者操作

1. 从历史会话中的坏报告卡打开“未核验的已保存报告原文（仅供排查）”，先读红色警示
2. 在“查找原文字段或值”输入可理解的关键词，例如“毛利率”，点“查找”或按 Enter
3. 按原字符串顺序查看命中总数和位置；用“上一处／下一处”检查同名字段。命中旁保留前后原文，可以明确展开更多前文、后文；未命中时明确提示
4. 在有限宽度的原文区用普通纵向滚动阅读字段名、原始值和邻近结构；所有结果仍标明未核验。需要完整文本时展开“完整原文 · 自动换行（未核验）”
5. 点“下载未核验原始文本（.txt）”。文件名以 `unverified-saved-report-` 开头，内容是原存储字符串的 UTF-8 字节，没有添加标题、警示、BOM、缩进或额外换行。警示存在入口和文件名中，不混同被封锁的常规报告导出

查找区没有表单提交或业务写入；不会产生假未保存状态，也不会清除已有业务草稿。相同报告、相同原文和相同账户／身份／数据集下的会话刷新保留刚输入的关键词、展开范围和滚动状态。新报告、改变的原文、旧上下文和已移除入口不会复用这些状态。

## 原文合同

- 显示及查找不解析报告 JSON，不重新序列化数字，不推导新的财务结果。超安全整数、数字拼写、JSON 转义、引号和空白不被数字格式器重写
- 原字符串使用独立的 JSON 字符串封装穿过 HTML 属性；只解码这个传输字符串，不解析其报告内容。下载从这个原字符串构造 UTF-8 字节，绝不从 DOM 的可见文本反推原件
- 阅读区自动换行仅改变布局；原有 CR/LF 用字符引用传入显示区，避免 HTML 对字面换行的规范化影响原字符。命中摘要的省略号明确表示前后还有原文，完整原文和完整下载保留
- 无效 JSON、空字符串和非对象 JSON 原文仍能原样阅读、查找和下载。不是字符串或含不可保真 Unicode 代理项时，明确说明无法保证原字节，不将一个对象的新序列化结果冒充原文
- 报告 audit 的原文、报告记录和完整性检查在同一个 owner-bound 读取快照中返回。无法解码的结果不再先阻塞于 runtime 读取；页面保留失败状态和原文。常规报告导出返回 409；没有新增写入或权限

## I10 原生任务更新（尚待执行）

原任务继续：实际导入合成资料 → 在助手提问并明确批准 0 外部调用 → 阅读完整性有效但研究结果受限的 20% 报告 → 声明只改变保存结果一个标量的隔离故障 → 从会话历史普通入口回来 → 读取不可用原因和原问题 → 原文入口输入“毛利率” → 逐处检查屏幕中的命中及前后文 → 普通纵滚读字段名、原始值 → 实际 TXT 下载并核对原 UTF-8 字节 → 页面重载仍拦截 → 同会话另行批准新报告 → 回到旧坏卡仍拦截且所有旧记录保持。

查找阶段不计算目标偏移、JSON 层级或巨大横向滚动距离；选择下一处依据阅读器实际展示的匹配和上下文。字段／数值预期仅用作独立结果断言。命中发现后保留普通纵向滚动与只读可见性观察、原图、录像及 trace，另记录完整原文区没有横向溢出和真实下载 SHA-256。

300 秒进程／15 分钟任务预算、七次明确助手写入、零供应商调用、原损坏保存、原记录不恢复，以及原证据打包要求不变。原 I10 单行横移的既有结论不升级为此阅读器的原生验收；必须审阅新版本实际图片与完整旅程。两个完整性有效的确定性 20% 报告仍可能是 degraded／结果受限，不能宣称研究全面正确。
