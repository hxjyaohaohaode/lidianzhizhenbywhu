# 报告历史与已删除对照的恢复边界（2026-10-05）

## 实际问题

原报告接口只返回最新200条，虽提示还有记录，却忽略offset/limit。隔离复现使用一份实际完成报告及200份明确标注的存储容量副本，验证第201条原报告无法从列表找到；副本不冒充已执行研究，原报告详情未改变。

保存对照成功后，使用同一request_id重试原本能找回同一记录。但明确删除后，旧提交重试又返回201并创建新ID，违背删除意图。此问题使用真实账户、两份合成数据、保存/重试/删除/旧重试API完整复现。

## 修改后的行为

报告接口支持offset 0–1000、limit 1–200（默认200），返回total、offset、limit、has_more和原身份/企业范围；每页按保存时间及ID排序。界面每页20份，页码在地址中，浏览器返回与刷新能定位同一页。记录数量变化导致空页时可返回第一页。

“对比两份报告”在用户打开时按原范围读取最多五批、每批200条的摘要，使较早报告也能被选择。读取过程中离开/换范围则不继续后续批次或覆盖新状态；明显的数量变化、重复/缺失分页或失败不会发布部分列表。分页读取不执行任务、重算结果或修改授权。偏移分页不是数据库跨请求快照；并发新建/删除时应重新读取核对。

对照删除在同一事务保留原删除审计，并把创建标识放在独立审计行的普通列中，只保存比较ID和内容摘要，不保留已删除的完整输入。恢复查找不依赖该绑定的JSON内容；原删除元数据或独立绑定元数据损坏时，已知被删除的标识仍拒绝复活。没有声称数据库全部审计行被删除或普通绑定列同时被改写时还能恢复不存在的证据。旧标识再次提交返回COMPARISON_REMOVED，内容改变则返回IDEMPOTENCY_CONFLICT；明确采用新的标识才可创建新对照。判断按原账户隔离，并优先于当前数据可用性检查；其他账户不会继承删除凭据。旧版本已发生而未保存标识的删除记录无法补造关联，此修正不声称追溯阻止那类旧请求。

## 检查范围

本地API与编译视图/transport检查覆盖201条取回、原报告保持、作用域与非法边界、跨页选择、最多1000条的五批限制、迟到读取不发布、删除后幂等拒绝、明确新建、账户/CSRF/版本控制和损坏无关审计行。页面真实滚动、跨页选择与返回还需新的原生证据；未声称真实用户、所有并发组合或全产品通过。
