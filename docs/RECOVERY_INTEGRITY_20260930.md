# 持续使用、迁移与恢复的一致性

日期：2026-09-30 UTC。基线内容来自企业对照联动版本；本轮只处理实际复现的持久化与故障路径，不增加业务数据、供应商或研究公式。仍使用现有审阅分支，未合并或部署。

## 根因与接受条件

| 根因 | 实际问题 | 修复后的合同 |
|---|---|---|
| 版本检查分散在迁移中途 | 不支持的自主编排版本被拒绝前，工作区版本已经升级；后续迁移失败留下半套新表 | 所有已知版本先只读检查；建表、索引回填和各扩展在同一事务提交，嵌套步骤使用保存点；失败关闭连接 |
| 恢复把旧记录视为可信输入 | 改变历史内容、保留旧哈希仍能恢复成新有效版本 | 元数据保持可读；坏内容不计算差异、不提供恢复控件。哈希、数据结构与归一化单位校验通过后，同一所有权/版本事务创建新修订并记录来源，不改旧记录 |
| 备份只验证数据库页面结构 | `integrity_check` 通过仍可能存在孤立外键；新目标旁边的旧 WAL/SHM/journal 文件会被 SQLite 接管 | 对完成的快照同时做结构与外键检查；目标、回执和 SQLite 配套文件冲突均拒绝，失败清理本次新输出 |
| 旧执行器在故障边界外读取凭据 | 数据库恢复后缺少、损坏或不匹配的主密钥导致整个旧版批准任务失败，已有本地结果丢失 | 新旧执行路径都保留本地报告并明确受限；密钥加载失败不外发、不伪造模型结果、不重建替代密钥，异常详情不泄漏 |
| 当前子记录与已删除父记录脱节 | 已删除所有证据后，孤立审阅仍占满额度；删除会话后的验收/claim 审阅也无法访问和整理 | 明确删除时同事务清理对应当前子记录；旧版遗留孤立记录仍可账户导出，但不占当前可用额度或遮蔽当前列表；不扩大有效记录上限 |

迁移不自动修补不一致数据库、不重算历史哈希、不改 schema 标记来绕过拒绝。结构/哈希检查不是第三方认证，不能防止拥有完整数据库写权限的人重写全部内容和校验值。

## 恢复验证采用完整旅程

新增真实 HTTP 旅程在运行中的服务上备份，核对回执散列与外键后，把副本放入全新 DATA_DIR，启动第二个 Uvicorn。两个已有账户重新登录；核对数据修订、导入回执、报告、工作区对象、产物和事件链；检查跨账户访问仍被拒绝。随后仅在副本中恢复历史修订，验证版本递增、原始服务数据库不变、历史报告不变。

迁移另有独立子进程强制退出用例：后段扩展已经执行但尚未提交时结束进程，旧库内容和版本标记保持不变，下一次正常启动可完成迁移。此测试不等同断电、磁盘损坏或所有文件系统的耐久性认证。

删除的父记录仍遵循原有用户确认和版本要求。当前子记录清理不影响独立保存的报告快照、行动验收原文、策略评估或审计历史。旧遗留记录保留导出，不自动认定其缺少父记录就是可以清除的历史。

## Windows CI 路径断言更正

随后 Windows CI 的 8 个失败均来自测试把 `readlink()` 返回的扩展长度路径直接与创建时的普通路径作比较；备份已按预期拒绝冲突，链接也仍存在。[Python 文档说明 Windows 会返回通常带扩展前缀的替代路径](https://docs.python.org/3.13/library/os.html#os.readlink)。这不作为 Windows 整体通过的证据：当次原生浏览器与后续启动检查被前置失败阻断。

本次仅修改测试：操作前后严格比较操作系统返回的原始目标字符串，并独立用 [`resolve(strict=False)`](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.resolve) 核对目标身份，因此仍检查悬空链接。原有 12 组文件/链接冲突均保留且不跳过；新增 10 个反向用例证明改变目标、换成普通文件、删除、改写等价链接或错误预期目标仍会失败。没有修改生产备份保护。当前修订的 Windows 全流程仍须重新执行 CI，不能以本地 Linux 通过替代。

本次路径断言修正的最终本地检查完成于 **2026-09-30 20:07:39 UTC**：896 后端、150 前端、15 组真实 HTTP 旅程与其他整套检查通过，后端跳过数为 0。独立运行的备份测试 32 项通过；这些数量不相加。记录见 `evidence/backup-path-ci-fix-20260930.json`。新的 Windows CI 尚待该修订实际执行。
