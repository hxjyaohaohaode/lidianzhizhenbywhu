# 研判报告缺口与复盘读法（2026-10-05）

## 原问题与来源

实际 8bd 原生验收截图 `ui-current-saved-experiment.png` 显示，缺口表主列为 `sales_volume`、`production_volume`、`gmps:lithium` 等标识；复盘是 `evidence/missing`、`gaps/needs_input`，两项原因均为“查看对应产物”。本次已直接查看原图及相应原像素裁剪。

源码来源：`server/research_gaps.py` 保存字段、路径、季度核验事项及不可计算规则的原公式；`server/adaptive_runtime.py` 复盘只保存节点、状态和可为空的 reason/error_class。此前前端只查不含上述标识的 metricNames，复盘直接输出节点和状态。没有 reason 不代表有一个可以从节点名推断的失败原因。

## 本次只读变化

- 实际 `adaptiveReport` 将同一冻结报告交给缺口与复盘渲染器，不新增请求或业务写入
- 字段、规则和节点用中文；未知旧标识明确显示未知和原标识；原 JSON 仍折叠保留
- 缺失期间来自原字段路径、保存的 field_coverage 或 MISSING_FIELDS findings；季度核验行补出保存的具体字段
- 规则定义直接读取原 unavailable_rule_components 或 dimensions.formula。只有 `rules-3.0.0` 的已知输入对应关系可展示其冻结 series 中的原值；不重新计算得分，不推断缺失值，DQI 盈利项沿用原保存 metric
- 当前期和指定基期均只读原报告的期间。null 标为未提供，缺键标为未记录，0仍显示为0；未记录的历史期间不从当前资料补齐
- evidence/missing 只有在同一报告明确保存空 citations 时说明冻结引用0条；gaps/needs_input 只有在同节点产物状态一致且确有 items 时说明清单已生成、相关输入仍需核对或补充。数值完整但分母为0也可能导致规则不可计算，不能一律说资料缺失。原 reason 优先；状态冲突明确提示；没有依据时说明具体原因未记录
- 补录指引对应“经营数据”与“证据资料”，保存后须新建研判，旧报告不会自动更新

服务端、原公式、规则权重、历史存储、JSON/Markdown 导出代码以及 CI 注册均未修改。助手“输入质量与缺口”使用另一渲染路径，不在本次修改范围。
