# 实现架构与数据合同

模块化单体：FastAPI、严格Pydantic合同、SQLite WAL、原生TypeScript模块。服务器唯一计算财务结果；前端不补造数据。应用和有限任务队列同进程；同一数据目录禁止多进程共享执行。不是分布式Agent平台。

|store / workspace_store|事务、所有权、迁移、修订、审计、事件锚点、业务对象|

## 数据与所有权

账户身份仅来自服务器会话，不能用userId、内部Header或代理IP提升权限。数据修订、计划审批、任务控制和策略激活用事务及版本检查。所有工作区对象按user_id隔离。删除会话级联删除运行、图、断点与调用记录；独立批准计划等历史副本按照明确的清理操作处理。

原有表与旧调用兼容路径保留，新增adaptive_schema、adaptive_controls、adaptive_graphs、adaptive_checkpoints、adaptive_calls；workspace_objects增加assessment/strategy/strategy_active/strategy_evaluation。迁移是增量且幂等，遇到未来schema版本拒绝写入。获奖TypeScript库不支持无损直迁。

## 计划与执行

计划冻结财务/证据/已批准记忆/偏好/目标/可选历史。绑定版本、内容哈希、供应商主机/路径/模型、当前策略版本和24小时审批期限。数据或策略变化需要重新预览，不直接用旧授权。执行期间每次外发再次核对当前身份版本、数据版本、批准记忆、资料状态及有效期。

依赖图为受限DAG：只允许注册能力和最多24个节点，严格验证重复ID、未知依赖与环。基础门禁不可被模型删除。只读准备节点并行；模型专家可由限定规划选择并行或显式依赖，反证审阅等待相应产物。最多3并行节点、8次累计外部尝试、2轮有界修订；采用事务预留调用预算，暂停/重启不重置计数。

模型规划只接收问题、目标、研究模式、能力目录、质量警告和证据数量，不接收原文记忆/证据片段。后续专家按原授权上下文、只读工具结果与前序假设工作；实际片段ID、记忆ID、请求摘要、模型身份和usage写入调用台账。候补服务需提前披露同一输入范围。模型不能新增URL、调用任意代码、自动写入业务记录、搜索或交易。

每个节点的输入快照摘要、输出产物摘要、完成事件和执行配置互相对应。继续任务时重新核对，再复用完成产物；只读未完成步骤可重算，未知外部调用保守标记且不重发。它防止普通路径无声错配，不抵御数据库管理员重新生成整个库，不是第三方公证。

## 前端与同步

15个工作区共用企业范围。运行视图读取真实图版本、节点事件、时间、断点和调用记录，不以定时动画冒充Agent工作。原生SSE优先，故障时明确切换到有上限退避的只读轮询；终止事件与在途读取竞争时合并补读，防止状态停留。切页销毁订阅，过期身份/账户切换丢弃迟到响应。

一般变更游标仍只提醒刷新，不覆盖用户草稿。不自动重试任何写入；幂等键和乐观版本是最终保障。缩放/清单/键盘节点详情、焦点保留、断网提示、主题、移动抽屉和减少动效各有明确行为。原始品牌PNG/MP4从web/brand静态提供，同时保留/images/logo.png与/loading-video.mp4路径。

## 研究语义合同补充（2026-09-30）

`question_scope` 是两个本地助手与批准计划共用的有界问题范围解析器。财务目标季度与比较方式明确冻结；无法明确解释的日期/年度/多目标或问题与表单比较方式冲突会阻塞，不通过模型猜测范围。原始完整数据哈希用于归属/审批/审计，`analysis_dataset` 仅选择实际计算的财务前缀；策略案例去重也按实际使用的前缀，不能用未使用的后来季度扩充验收样本。

`research_context` 统一数学产物投影和可引用目录，`grounded-claims-v2` 在旧结构上增加可选数学引用。调用台账记录实际发出的目录并锚定事件；结构复核按产生解释的具体成功调用核对，不能借用别的专家见过的资料/数学引用。服务器解析保存值、单位、期间和完整产物哈希，前端与导出直接显示这些归档值。省略的工具细节不产生引用权限。

`research_gaps` 使用原计算器组件和血缘导出缺口，不维护第二套评分公式。计划冻结核查日期，运行与回放复用该日期；回放v3使旧评估重新执行，保持显式激活门禁。旧无新增字段的报告与快照保留兼容回退，不迁移重算历史业务结果。

## 跨工作区来源与生命周期补充（2026-09-30）

`business_provenance` 为行动和跟踪解析服务器可信来源，保留原始数据/身份/报告/消息/告警绑定；`source_impact` 与 `report_impact` 是独立只读当前适用性投影，绝不重写历史。人工验收证据保存有界原文与审阅快照。`/services/history` 为已删除或缩小的身份/企业范围提供账户内只读入口，不能据此恢复旧授权。

`saved_experiments` 复用原数学实现验证已保存实验，将显式选择的原假设、目标季度、核查日、输出及指纹贯穿审批、执行、引用和回放。新预测冻结核查日期；旧无日期预测不凭空补值。`dataset_import_receipts` 与目标数据修订绑定，预览清理不删除已确认的处理回执，账户导出包含此表。

`evolution` 以财务输入分组独立样本，但组内全部验收任务均保留；人工解释复核集合绑定回放授权，新增/修改复核后需重新确认。业务核查日统一采用界面声明的 UTC 日期，冻结报告/实验继续用原日期。完整根因、15工作区覆盖及验证边界见 `SYSTEM_INTEGRATION_20260930.md`。

## 保存的企业对照

`saved_comparisons` 复用原始 `models.calculate`，不建立第二套财务公式。记录 2–8 个成员快照、修订/哈希、共同季度、同/环比、单季归一化口径、计算日期及人工可比性说明；工作区扩展标记为 3，以阻止旧程序忽略多企业批准合同。新注册的第 17 项能力 `comparison` 只执行明确选中的冻结对照，不读取未批准企业。

计划通过 `comparison_artifact` 的 ID/版本/哈希选择；全部成员在预览、批准和每次外发都须核对。主企业原有证据/记忆检索保持原范围。专家上下文只投影五项已计算比例与成员限定引用，引用同时绑定原输出哈希；整节裁剪时同步移除引用权限。报告保留完整冻结产物，行动/跟踪只复制有独立投影哈希的五指标摘要。来源删除不会补查当前值伪造历史。

回放协议 `local-capability-replay-v4` 新增比较计算结果不变性门槛；同一主企业财务输入的不同同行场景全部回放，但仍保守归在同一独立输入组，不因多建对照虚增样本。旧评估需重新回放并明确激活，历史报告不重算。
