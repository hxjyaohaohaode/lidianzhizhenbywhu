# 反向资料覆盖与旧回放版本保护验收（2026-10-05）

## 修正的行为

此前只要有任意引用，标签分组就返回 completed；仅背景或支持资料因此也能满足人工选择的 counterevidence 能力要求，造成 3 项覆盖改善并允许激活。现在生产执行和本地回放都要求存在人工标注为 contradicts 的引用。缺少时返回 missing 和具体原因，同时保留原支持、反向、背景分组。

该门槛只检查人工反向标签是否存在，不证明资料真实、相关、有效或构成逻辑反证；没有额外要求 supports。needs_input 仅对已生成具体待补工作清单的 gaps 算覆盖。数学实现未改动。

回放版本从 v4 升为 v5。旧评估保留原始内容，概览另附 implementation_context 表示实现版本是否适用；它不代表全部当前激活门禁。旧活动策略返回内置规划规则，并说明实现版本变化，不能误报为用户撤回授权。激活仍重新执行当前案例、基线、候选和产物一致性门禁；旧回滚依据不可绕过版本变化。

每例 source 仅记录冻结运行的问题、企业、目标季度、数据修订和数据哈希；反向能力计算摘要保存实际状态、输出哈希、原因、限制和各标签计数。网页报告、Markdown 导出与专家上下文同时保留具体缺口。旧报告和评估不从当前资料回填。

## 可复现材料

独立审计包包含冻结 f75 源码、修复源码逐文件哈希、reproduce_counterevidence.py 五组 API 脚本、reproduce_v4_upgrade.py 跨版本脚本和显式合成财务夹具；各运行目录保留完整业务 API 请求/响应、评估、历史报告前后哈希、模板输出、日志与结果清单。认证凭据、Cookie、业务数据库和供应商密钥未纳入材料。
