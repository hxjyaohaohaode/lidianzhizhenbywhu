# 实验保存结果不明时的恢复（2026-10-05）

原问题由完整生产表单监听器、真实 API/实验列表/同步模块和明确命名的进程内传输桥复现：
服务端已经保存情景或预测实验，但响应丢失后，原表单允许再次提交，产生第二份不同 ID
的实验并占用另一份额度。在199份已有记录时，第一次未知结果恰好占满200份，重试反而
返回容量不足。普通防双击、账户隔离和数据版本校验不能解决这个先保存后断响应的路径。

## 实际修正

新表单在发送前保留原请求和稳定提交标识。相同账户、相同标识、相同归一化内容的明确
重试返回原实验，不重新计算、不生成新的实验、审计事件或额度。原数据后来修订以及
当前容量已经用满，不会阻止找回已经完成的原结果。改变请求却复用旧标识返回冲突。
实验仍按本账户的数据范围共享，没有改成服务身份私有资产。

服务端校验首次保存的完整载荷摘要、原请求、数据版本与快照绑定后才确认重试结果。
内容或回执缺失/损坏返回 `EXPERIMENT_INTEGRITY`，不会以当前内容补造旧摘要或重新计算
成一份假装相同的结果。摘要检测记录一致性，不认证原财务事实。删除实验只保留原提交
标识与请求摘要的既有审计记录；原标识再来时拒绝重建。删除账户沿用原级联清理规则。

网络失败后保留填写内容和原请求；用户必须明确重试。页面重载后，待确认区显示原
参数、数据修订和用途，再次发送的是用户核对的原请求。用户后来修改的新草稿不被
迟到结果覆盖，切换账户或服务上下文不展示旧响应的成功提示。后台同步不会自动重发。

每个账户在本标签页最多保留20笔、160 KB待确认记录；写入前必须能保存这些恢复信息。
无法保存时不发送新请求。已移除数据或其他服务上下文的记录可以从账户级管理窗口
查看并明确结束本地重试；这个窗口不提供业务重发，不删除已保存实验，且拒绝旧账户
控件和仍在发送的请求。结束前说明原提交可能已保存，之后另建相同内容仍会是新实验。

## 边界与验证

- 本标签页的恢复便利依赖其会话存储仍保留；关闭或清理标签页会结束这份本地便利，
  不删除服务端已保存实验。服务器提交标识与删除回执独立持久化
- 未带提交标识的旧 API 调用继续兼容，但不能宣称它们获得相同的幂等保证；新界面
  始终发送稳定标识。旧实验不从今天的内容回填创建摘要
- 第一版独立检查发现不可见记录占满恢复容量，以及损坏记录被误报为已确认；修正后，
  独立23项整合观察及3项真实生产同步控制复核通过，原失败与反例记录保留
- 实际后台同步保留已审阅的v1表单；明确同步刷新会替换原表单并显示原v1恢复控件。
  没有把单独调用底层刷新函数、手工改状态的模拟当作已经发现的普通界面缺陷
- 独立证据来自生产前端模块与隔离 TestClient，包含真实保存后丢响应、重载、配额、
  作用域、20笔不可用范围记录管理、损坏回执拒绝及原业务记录保持；它不是原生浏览器证据

本次没有迁移数学公式、重写原实验/报告、自动重试业务动作或调用真实供应商。
完整整合和原生恢复流程各自记录，不以局部测试数量代表完整产品验收。
