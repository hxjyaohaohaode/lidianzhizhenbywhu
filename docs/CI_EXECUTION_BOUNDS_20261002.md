## 证据如何读取

- `evidence/pytest-progress.jsonl`：每行立即刷新，包含已收集节点、测试开始/结束、setup/call/teardown 的开始/结果、墙钟及进程 CPU 时间。只保存节点身份、阶段、结果与耗时，不记录 fixture 值、业务数据、凭据或断言正文
- `evidence/pytest-progress.stacks.log`：卡住或崩溃时的线程文件/函数/行号，不含局部变量
- `evidence/pytest.log`：原始输出、超时信息和最慢 20 项；`evidence/pytest.xml` 仍只由 pytest 自己生成
- 外部终止或硬超时会留下完整的最后一行进度。缺少 `session_finished` 就没有本次完整测试结果；最后一个未完成的 `phase_started` 可定位所处阶段
- 正常结束时核对收集与完成节点，短路而未执行的测试不能变成成功；普通断言失败与超时分别记录。fixture teardown 失败仍是实际失败
- 新 CI 尝试清理已知生成文件，再连同当前运行上下文上传；直接本地执行 `verify.py` 也会在 pytest 阶段开始前清理当前 JUnit、进度和栈文件。清理失败则该阶段失败且不启动 pytest；避免启动失败或 kill 后误读前次完整 JUnit。既往历史目录及业务数据不清理

900 秒是当前证据支持的单次修正。若新执行仍超时，应根据新进度/线程栈诊断具体阶段；本修正不授权继续无证据加时。若整体吞吐量继续增长，后续可单独评估带完整覆盖核对的分片方案。
