# 本次代码审阅与改动依据

> 这是早期审阅记录。2026-09-27 的依赖升级、原生浏览器验收和当前覆盖范围见 [VALIDATION.md](VALIDATION.md) 与 [DEPENDENCIES.md](DEPENDENCIES.md)；下文的未测项按当时快照理解。

本次直接以用户提供的上一交付ZIP解压结果为基线，不仅阅读README。基线pytest为206通过；原ZIP保持不变。产品方案在改码前形成内部三轮范围/威胁/验收检查，不随交付附上未落实的愿景计划。

关键修复与可验证变化：

- 生产服务去掉任何“测试模式允许绕过模型审批”的状态开关。旧外部run请求必须改走计划；旧worker测试若需特定状态只在测试夹具直接构造，不是生产后门。
- 资料范围过滤发生在排序及限额之前，避免大量无关公司文档挤出当前公司证据。
- 外部调用逐次核对排队后的撤回和版本；用于报告的“实际发送记忆”只在确实派发时记录，不把配置存在当已使用。
- 输入文件预览和财务入库分离，复制、编辑、撤销有版本与指纹校验；不写假数据等待后续替换。
- 修订触发器覆盖旧新数据写路径；重跑迁移不会自动修复被篡改的哈希链而掩盖异常。
- 事件、节点产物、完整报告与快照进行交叉一致性检查；UI不再仅凭事件链一项就显示全部记录有效。
- 限制总上传时长，并为提前拒绝响应补齐隐私和安全头。
- 删除默认样例入口；风险PDF从核心依赖移除并执行版本门禁，避免仅在文档里提醒却继续解析。
- 前端完整更换为11工作区，真实API输入输出；修复字段合同、返回预览丢失手工输入、延迟可见元素验收方式、移动抽屉、重复toast堆叠与退出登录残留对话框。
- 模板只复用问题；旧报告标记数据修订过期；行动、资料审阅、计划、实验有独立删除边界，避免“删除原件等于清除全部副本”的错误承诺。

所有测试都不能等价于逐行形式化证明。外部真实模型/搜索、原生浏览器网络、依赖全量漏洞审计及目标设备尚有明确未测项。最终结果以VALIDATION与实际日志为准；初期失败日志是修复过程证据，不冒充最终通过。
