# 三输入策略成功链原生验收候选

日期：2026-10-12。基线：main 5d08b3535d8da4d19909bf34230d8ff55f001da9。

本轮只增加测试、验收入口及 CI，不改业务代码、数学公式、品牌或既有报告。
旧 L9 一输入授权链与其 Linux 地域访问 hold 保持原样。新 L13 使用此前已获准、可运行原生浏览器的 Windows GitHub runner，具有独立证据目录；它不代表被阻止的 Linux L9 已通过。

## 原控件路径

1. 新建隔离合成账户；原证据表单与审阅表单保存一条明确合成的反向标签资料。
2. 下载原空白 CSV 模板，依次导入三份财务数值不同的两季度输入。收入分别为 100000、125000、160000 元，成本均为 80000 元；其余未提供字段保持缺失。
3. 原计划表单明确选择“遵循已激活策略”，关闭本地自动追加核查，保持外部模型未选。分别批准执行三份本地报告，并在原验收表单逐份明确授权冻结输入回放。
4. 原“从验收生成并回放”按钮执行真实回放，读取三输入、开发/保留分组、三项改善、零回归和两侧数学摘要不变。界面中的逐例能力与资料分组保持实际状态，不把计划节点冒充完成。
5. 在真实激活确认框先取消，要求零写请求且版本不变；再确认一次，要求精确目标及 expected_active_version 的一条写请求。刷新、注销、重新登录后核验保存状态。
6. 从当前计划列表找回激活前的未执行计划，使用原批准按钮接收 PLAN_STALE 及可见恢复说明，不创建运行。新预览增加反向能力。
7. 回滚也先取消零写，再明确确认一次。再次刷新与重新登录；新计划恢复内置规则，原报告、来源、计算、验收、候选和回放内容保持不变。从真实报告列表再打开第一份报告核对原值。

所有业务写入只能由可见控件产生。只读 API GET 用于核对保存对象；不使用写 API、数据库注入、虚构 eligible 或关闭安全限制。合成人工标签仅测试本地能力覆盖，不证明资料真实性、模型准确率或生产效果。外部模型/供应商实际调用应为 0。

## 隔离与证据门槛

- 新入口只允许真实 Windows GitHub runner，同时核对 os.name、sys.platform、GITHUB_ACTIONS、RUNNER_OS；无放宽参数。
- 保留既有 300 秒浏览器预算、15 分钟 job 预算和默认浏览器安全设置。
- 保存三份实际 CSV 与 SHA256、可见操作及截图、完整原生 trace/video、只读原对象、确认/取消写请求计数、源文件前后身份。
- 成功收据必须包含三份完整合成输入及当前 scenario；失败只能保存实际已生成的证据，不继承旧成功。
- 当前本地可执行纯断言反例和无网络 ASGI 契约；它们与 Windows 原生浏览器结果分开记载。此文档本身不是原生通过证明。
