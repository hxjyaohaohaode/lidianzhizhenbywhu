# Packaged TLS/crash diagnostic identity — 2026-10-12

## Identity contract

`tls_proxy_check.py` and `crash_dispatch_check.py` share `source_identity.py`.
A manifest at the application root or its immediate parent takes precedence;
multiple manifests, invalid manifests and incomplete source sets fail closed.
There is no fallback to Git after an invalid manifest.

The release schema requires exactly `commit`, `tree`, `file_count`, `status`,
`source_set_sha256`, `files`, with optional `artifacts`. Every source record's
canonical relative path, byte count and SHA-256 is checked. Duplicate JSON keys,
case/Unicode-colliding paths, traversal, absolute/nonportable paths, symlinks,
hardlinks, missing files and unlisted application source/assets are rejected.
`source_set_sha256` hashes only the canonical JSON `files` array.

Optional artifacts are strictly typed Git-bundle records: `type`, `path`,
`bytes`, `sha256`, `requires_commit`, `contains_commit`. Paths are relative to
the manifest directory and must be outside application source. Attachment bytes
and hashes are verified; bundle history claims are not inspected by this helper.
The declared contained commit must equal the manifest's declared commit.

Reports use `kind: package-source`, `git_head: null` and separate
`manifest_declared_commit`/`manifest_declared_tree` fields. This proves consistency
with the supplied manifest, not publisher authenticity or Git provenance. Changing
both a manifest and its files cannot be detected without a separately trusted
external digest/signature. Before/after identity also binds the raw manifest hash.

Without a manifest, only the application's own `.git` directory/file is accepted.
Git runs under the existing OwnedProcess stage budget and cleanup registry. Its
reported top-level path must equal the application root, and inherited `GIT_*`
redirectors are removed. `git_head` identifies verified Git metadata;
`worktree_matches_commit: null` explicitly does not claim a clean working tree.
`files_sha256` binds the actual diagnostic/runtime/fixture bytes inspected.

Only unlisted root installation/cache directories (`.runtime`, `.venv`, `venv`,
`node_modules`, `.pytest_cache`, `.git`), generated bytecode for declared Python
source, and non-code evidence reports may be additional files. Declared files
are always verified even if they are historical evidence. Diagnostic application
children use a fresh temporary Python cache prefix and disable bytecode writes.
Installed dependencies and runtime data are outside package-source identity.

Run diagnostics with output outside the application source directory. Do not
change the manifest status, attachments or source bytes between the before/after
checks. Updating a declared historical evidence file invalidates its package hash.

native-browser acceptance claim. Final no-Git TLS/crash acceptance belongs to the
frozen final package, after its new manifest and history attachment are built.
