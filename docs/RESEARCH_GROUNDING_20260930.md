# 第三轮：问题—数学—解释—回放闭环

日期：2026-09-30。基线：`2efcf387cdadcd41ed5c880a8f484049b92a07c5`，延续现有审阅分支；没有合并主分支或部署。本轮从实际调用输入与历史回放复现缺口，未使用外部模型调用。

## 已修复的核心断点

1. 情景数学结果过去使用错误投影字段：本地计算得到的 `result`、毛利额变化、盈亏平衡倍数与方法限制未进入专家上下文。现由 `research_context` 统一投影实际字段，并保留完整产物哈希。
2. 模型解释只能引用财务指标和资料，不能明确关联情景/预测产物。新增可选 `tool_reference_ids`，只接受服务端在本次具体专家调用中实际发送的引用目录；数值、单位、期间和哈希由服务端从已保存产物解析，模型不能提交自己的数值替换。预算删去产物细节时同时撤销其可引用目录。旧版执行器拒绝数学引用，旧报告保持只读兼容。
3. 财务规则计算的警告依赖运行当天，季度变化会令历史回放哈希误报数学回归。新计划冻结 `analysis_as_of`；本地工具与回放采用同一日期，公式、权重和阈值不变。回放实现版本升级，旧评估需重新运行才能激活。
4. 助手过去把未知问题变成最新季度的毛利/现金概览。两个本地助手共用显式问题范围：现金流金额与现金收入比区分，支持单个已保存季度及同/环比，年度、多个目标季度和缺失季度明确要求澄清；无法识别的主题不填无关指标。
5. 历史问题向 Agent 转交时，计划冻结目标财务季度，计算/情景/预测只使用截至该季度的财务输入。原始完整数据仍在快照中供版本、所有权、审批和审计核对。报告与计划披露范围；这不是历史信息可得性回测，资料仍按本次授权检索范围使用。
6. 数据缺口过去只检查八个最新期字段，遗漏规则组件、净资产与指定基期的不可计算项。缺口计划现从原计算器和血缘实际结果导出具体待核查项，不自动插值、不填零、不替换同/环比基期。

## 可用路径

- 研究助手输入 `2024-Q2经营现金流是多少`（该季度必须已存在）→ 查看金额、比率、字段来源与期间 → 交给 Agent 深入研判 → 预览目标季度、资料范围和实际上下文 → 明确批准 → 报告中核对同一季度与数学结果
- 配置且明确批准情景/预测的专家计划 → 查看解释下的“数学依据” → 核对保存值、单位、期间、产物引用和 SHA256 → 导出 Markdown / JSON，保留同样依据
- 输入年度或不明确的季度比较 → 清楚显示边界，不把最近季度当成年度结果；计划存在范围阻塞时不可派发
- 人工授权案例回放 → 使用原报告核查日期与财务期间；不改写旧报告，不宣称模型准确率或真实投资收益
