## L7：完整回答明确问题并找回原答复

从空账户的真实界面下载导入模板，导入12个季度的合成数据，明确选择万元显示和
简洁回答。问题分别要求四个财务指标及环比、成本预测、暂不支持的净利润预测、
同时预测收入与成本。

需要逐项核对四个指标、原始来源字段、目标季度和准确环比基期；成本预测必须明确
显示成本、历史输入截止季度、未来两个预测季度、万元单位和统计基线的限制。
不支持或多个预测目标必须给出真实拒绝理由，不能偷偷展示收入预测。刷新、重新登录后
按原问题找回相同的完整答复、比较范围和保存记录，不产生研究计划或模型调用。

这条旅程使用常数合成样本验证范围和表达，不证明预测效果。它不覆盖任意自然语言、
所有币种、所有身份切换或全部历史数据迁移。旧版本计划的币种与比较解释兼容限制
另见 [币种与比较基期边界](CURRENCY_COMPARISON_SCOPE_20261005.md)。

## L8：保存响应丢失后确认原实验

通过真实表单保存情景实验和成本预测。明确声明的故障只在一次真实提交已返回201后
中断该响应的浏览器交付；不伪造成功响应、不代替用户自动重试、不修改数据库。
用户先完整阅读未知结果及不会自动重发的提示，再明确确认原提交。

同一请求必须返回原 ID、版本、参数、结果和时间，不新增实验、额度或创建审计。
情景结果逐项核对收入13.2万元、毛利率27.58%、毛利额变化1.64万元，以及固定成本
2万元、变动成本7.56万元。成本预测必须显示原数据修订1、目标及历史输入截止季度
2024-Q4、2025-Q1/Q2的8万元估计和相应误差带限制。

第三次提交在未知结果后，通过实际编辑保存当前数据修订2，再刷新实验页。确认前
完整阅读原名称、企业、目标季度、修订1、四项假设、说明和来源指纹；同时填写的新
草稿必须保留。最终应只有三份原实验、六次用户明确提交和三条创建审计，原实验仍为
修订1，当前资料仍为修订2，无 Agent 执行或供应商调用。

这条旅程不覆盖20笔本地恢复容量及不可用范围的管理窗口；这些仍只有分别标注的
模块/API证据。标签页存储和旧 API 的兼容边界见
[实验保存结果不明时的恢复](EXPERIMENT_SAVE_RECOVERY_20261005.md)。
