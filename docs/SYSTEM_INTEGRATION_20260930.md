# 跨工作区业务闭环：合同、验证与边界

日期：2026-09-30（UTC）。基线：`97ce66c`，内容树 `25eec313`。本轮仍在现有审阅分支，未合并主分支、未部署。验证使用隔离测试夹具；运行时不添加演示企业、虚构业务数据或模板模型回答。

## 为什么改方法

已有审批指纹、账户所有权、冻结报告和调用台账能保护一次运行，却不能独自证明跨页面业务连贯。例如，同一数据的两个身份曾共享“已创建行动”标志；普通编辑能更换数据企业但导入修订不能；旧忽略记录会遮蔽新经营目标；相同财务输入的不同人工验收任务只留下最后一个。保存数学实验、行动验收证据和历史告警也缺少完整交接。

本轮按业务旅程核对来源、版本、作用域、失效规则和删除后行为，再修共同合同；测试按正向操作、输入变化、重复/竞争、清理和恢复组织。通过旧测试数量不能替代此类验收。

## 根因与共同修复

| 根因 | 原问题与同类排查 | 本轮合同 |
|---|---|---|
| 企业身份与写入口径分裂 | 普通编辑/导入/恢复对 company 不一致；企业名又关联目标、证据和行动 | 共同数据层禁止修订更换企业；所有写入口复用校验，编辑表单说明。其他企业需新建数据集 |
| 交接只有标题或裸 ID | 实验不能供 Agent 复用，行动/跟踪失去原消息、报告或告警依据 | 显式来源引用由服务端解析所有权、身份、版本与指纹；来源冻结与当前影响分别保存/返回 |
| 失效判定不完整 | 核查项未绑定身份/目标/证据，旧报告只看数据版本 | 核查实例按相关触发依据区分；报告/行动显示当前依赖变化，历史内容不重算；历史依据再利用需明确确认 |
| 去重单位错误 | 相同财务输入覆盖其他真实问题和人工 rubric | 财务输入仅决定独立样本分组；组内全部人工任务回放、同组同分区、全部受门禁 |
| 生命周期引用不完整 | 清理预览丢导入过程；删资料、会话、身份后下游难以解释 | 修订附不可变导入回执；行动验收冻结所选原文/审阅；孤立范围有账户只读历史入口；旧无绑定对象标为未知 |
| 人工反馈分层后失联 | claim 审阅、行动处理和整份报告验收互不显示 | 验收展示当前解释复核及关联行动的实际处理，授权绑定整个反馈集合；反馈变化需重新确认回放，不擅自把拒绝解释变成能力失败 |
| 核查日期依赖宿主时区 | 跟踪按 UTC，数学/到期校验按宿主本地日期，季度交界结论不一致 | 沿用已有跟踪/到期界面承诺，统一采用明确披露的 UTC 核查日期；报告、实验保存日期，回放使用原日期 |

UTC 是本版本的统一核查日约定，不代表企业当地报表已完成或披露。事件时间仍为 UTC；没有悄悄新增或推定用户的企业时区。其他业务日历须另行设计显式设置及兼容迁移。

## 核心链路与数据合同

1. **来源 → 数据修订**：文件预览记录文件 SHA-256/字节数、文件名、金额单位、期间口径、规范化及合并/替换影响。确认后生成与目标修订和输出哈希绑定的独立回执，清理预览不删除回执。没有保存原文件，也不宣称能定位原电子表格单元格。旧修订不伪造回执。工作区扩展 schema 从1增量升至2，旧应用拒绝降级写入，避免新来源合同被旧写入口破坏。
2. **数据 → 数学实验 → Agent**：新实验保存目标季度、计算日期及完整快照。选择实验提交 `{id, version, hash}`，必须是当前同数据修订、同目标期间；服务器用原计算器与日期复现结果。计划冻结原假设，禁止与冲突参数混用；批准及每次外发再检查来源。实际数学上下文、引用、报告导出和本地回放保留同一实验标识。旧无日期预测仍可看/导出，交给新 Agent 前需重新保存；不假造历史日期。
3. **报告/核查/助手/告警 → 行动 → 跟踪**：服务端保存原始数据版本、身份绑定、来源对象与内容指纹；对应报告/claim、消息/提案、核查实例或告警均可解释；从行动建立跟踪还冻结行动内容、版本和原始上游依据。来源已变化时默认拒绝，报告/告警表单提供明确选择历史依据。服务身份不是账户授权，不能借历史确认绕过当前所有权或范围。
4. **行动 → 验收**：状态机与乐观版本保留；选中证据携带当时看到的版本/哈希/审阅版本，确认再检查。历史验收保存文本、标题、来源地址及审阅快照；每份文本最多 12,000 字符，截断明确披露，完整指纹及原长度保留。后续撤回/删除只改变当前影响提示，不改写历史验收。
5. **跟踪 → 历史告警 → 后续核查**：跟踪始终评估当前保存数据，原始建立依据不会自动改阈值。每次告警保留规则与输入版本、值、阈值、期间。完全相同的规则保存不写新版本；标题/暂停切换不重复产生相同判定告警，实际判定条件使用独立修订。调查先展示历史依据，继续助手必须明确选择当前修订；由告警创建的行动保留告警来源。顶部企业范围与卡片企业标识一致。
6. **人工反馈 → 策略演进**：claim 复核和关联行动反馈集合包含 ID、版本与内容哈希；新增、修改复核或行动处理使旧回放授权上下文过时，界面取消默认勾选并要求重新确认。不同任务保留，财务样本不重复计数；当前授权、基线、候选和所有组内任务均在激活时再次实际回放。反馈不改变原报告或数学公式。

## 15 个工作区覆盖状态

“已接通”表示存在本轮具体业务合同和自动回归，不表示生产认证或所有浏览器均已验证。浏览器渲染证据单独见后文。

| 工作区 | 本轮覆盖 | 保留边界 |
|---|---|---|
| 我的工作 | 身份隔离、目标/证据触发实例、旧忽略与旧行动不冒充新处理 | 本地确定性核查，不是行业预警模型 |
| 研究助手 | 原消息→提案→行动/跟踪的冻结来源；旧消息不重贴为新修订 | 本地工具回答与外部 Agent 解释仍分别标示 |
| Agent 协同 | 原实验复用、审批、逐次外发复验、原报告与引用 | 无真实供应商凭据，本轮无付费调用 |
| 数学建模 | 显式目标/日期/版本，实验选择、参数锁定及导出 | 统计基线与机械情景，不声称投资预测校准 |
| 策略演进 | 同输入全部任务、复核上下文、授权变化、激活重验 | 本地能力覆盖，不是模型准确率/收益指标 |
| 经营数据 | 企业不变量、导入回执、修订/恢复与所有权 | 原文件未持久保存；不支持原地更换企业 |
| 证据资料 | 审阅变化传播至核查、报告适用性和行动验收 | 人工接受不等于系统事实认证 |
| 企业对照 | 维持共同季度和口径比较；异步结果不覆盖新页面 | 尚无保存的“对照产物”供报告引用，不虚称闭环 |
| 研判报告 | 冻结值与当前依赖状态分离；报告→行动/跟踪 | 历史内容保持原样，当前提示不是重写报告 |
| 主动跟踪 | 企业范围、历史告警核查、规则/数据版本及后续行动 | 仅服务运行时本地保存数据，非实时行情 |
| 跟进行动 | 来源合同、修改历史、验收原文/审阅快照与状态提示 | 不把行动完成自动解释成经营改善或因果效果 |
| 长期记忆 | 撤回/到期/修订在报告当前适用性中展示 | 原有人工批准和外发边界不放宽 |
| 身份与连接 | 孤立身份/范围的只读历史入口，现存授权继续校验 | 服务身份不是组织权限/RBAC；无新供应商 |
| 执行记录 | 原台账/断点/恢复保持；源记录清理影响明确 | 未知远端结果不自动重发；无绕过浏览器策略 |
| 偏好设置 | 目标变化影响实例、回执及新合同进入账户导出 | 导出为审阅材料，完整恢复仍须数据库在线备份 |
