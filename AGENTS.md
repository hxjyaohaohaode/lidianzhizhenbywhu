# Repository operating rules

Preserve the supplied logo and opening video byte-for-byte. Do not replace them with generic marks or fake loading progress. Preserve real business behavior and ownership history. Runtime company data starts empty; synthetic examples are restricted to isolated tests.

Plan before coding, but do not ship private internal deliberation as documentation. Each advertised feature needs a concrete code path, adverse checks and a dated execution record. Source code is authoritative, not an old README or report.

Never remove mandatory validation to satisfy a model plan. Only registered declarative capabilities, bounded graph size/concurrency/calls/revisions and disclosed input scope are allowed. A model cannot execute scripts, change formulas, perform trades or write arbitrary business data. No credential/base-URL exfiltration or prompt-derived permissions.

All writes require owner/version checks. External requests originate from a fingerprint-bound approved plan; recheck authorization at dispatch. Persist a dispatch reservation before calling. Unknown remote outcomes must NOT be retried on resume. Immutable checkpoints need hash and event-anchor checks. Pure duplicates are local deduplication, not billable model revision.

Evolution uses consenting human-assessed completed cases, deduplicated financial inputs and actual local replay. Respect original explicit depth and assumptions. Never self-grade a fake score; never activate without current-case/baseline/candidate gates and explicit human confirmation. Historical reports and mathematical formulas stay unchanged.

Before delivery run compile/typecheck/build, backend positive/adverse regression, frontend tests including event races, real Uvicorn HTTP/SSE/restart/backup chain and current rendered UI. Separate native browser checks from explicit DOM/API bridge checks; do not bypass administrator policy or relabel blocked checks as passed. Record external supplier calls accurately (test stubs are not live providers). Package no secrets, business DBs, caches, node_modules or font files.
